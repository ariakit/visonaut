Where a note goes, now that the work is in progress

The implementation started on 2026-10-08. So a changed answer now changes work that is in progress. Two places take your words, and each one has its own use.

  • A note or a changed selection in a panel of this page goes to the coordinator. Use it for the answer itself: to change a selection, to correct a reading of the record (for example of your note on D-SCALE-02), or to ask a question about a decision. The page puts that decision into the continuation prompt. Copy the prompt and give it to the coordinator. The change stays in this browser until you share the prompt, so the work does not see it before that. The coordinator merges the change into the record, publishes a new revision, and changes the text of each issue that has the answer.
  • A comment about the work of an issue goes to that issue on GitHub. Use it for a step, a pull request, an order, or a result of that issue. The plan table has the link to each issue. The tracking issue says that an instruction for a work session is the body of its issue, or a comment of the maintainer or of the account ariakit-bot. So the work session of the issue reads your comment there. A comment on an issue does not change this record: if it changes an answer, write the note in the panel too.
  • One caution for a public comment. The repository is public. Until the fixes of #257 are in production, a comment must not have the steps to use one of the 7 security findings (D-PRE-09). Give such a detail to the coordinator.

What a changed answer costs depends on how far the work is:

  • Before the work uses the answer. The record changes, and so does the text of each filed issue that has the answer. Each issue of the plan has its settled answers in full, so an issue with the old answer is wrong until the coordinator edits its text.
  • While a pull request with the answer is in work or in review. The work session stops that pull request or changes it, and a part of its work can be lost. On 2026-10-08 this is the case for the first steps of #255, #256, #257, and #258.
  • After a pull request with the answer is merged. The change is new work: a new pull request, and first a contract pull request if the change replaces a rule of the contract.
  • After a step that cannot be taken back. The 23 issues, the report ariakit/ariakit#7806, and the branch design-lab with its tag are public since 2026-10-08. An issue text can change, but a copy that a reader made stays, and a pushed commit can stay in clones and in forks. A published package version cannot change. A deleted image or a deleted row does not come back. The reason text of each decision says how to reverse the answer, and what stays.
  • A note alone. It does not change a selection. If a note conflicts with the selection, or if it asks a question, the coordinator asks you and does not guess.
