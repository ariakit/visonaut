Comparison settings come from pull request code

The trusted CLI compares each capture with the comparison object that the capture job wrote. The service checks that the result agrees with that object, and it has no limit of its own (apps/web/src/api/local-comparison.ts:529). For a white baseline image and a black capture of 100 × 50 pixels, threshold: 1 gives “unchanged” with 0 changed pixels. A pixel limit at its maximum gives the same outcome with all 5,000 pixels counted, when the rendering profile is the same. An unchanged capture gets no comparison row, so the review page has no item for it. The review data of a capture does hold its settings as text (apps/web/src/api/review.ts:523-526). The baseline keeps the old image, so the change appears in a later pull request that uses normal settings. 54 of the 94 pull requests since 2026-09-25 came from Renovate: a dependency update can have the same effect as an author.

  • threshold: 1: unchanged. No review item, no row, no reviewer. The check passes.
  • A pixel limit at its maximum: the same.
  • Image bytes equal to the baseline image: the same.
  • threshold: 1: unchanged, and the check passes. The run header says: “1 capture uses settings that are looser than the built-in policy.”
  • A pixel limit at its maximum: the same line.
  • Image bytes equal to the baseline image: unchanged. Nothing is shown.
  • threshold: 1: Submit fails with 409. The check does not pass until the setting is inside the limit.
  • A pixel limit at its maximum: the same.
  • Image bytes equal to the baseline image: unchanged. Nothing is shown.
