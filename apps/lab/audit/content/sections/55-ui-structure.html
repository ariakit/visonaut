URL model

A GitHub check stores its Details link: "The URL of the integrator's site that has the full details of the check" (GitHub REST API). The service writes two shapes: /runs/<id> and /pulls/<number>?check=<check ID>. Both must keep working. A check gets the /runs link with its first result, so the pull request page is mainly a page to wait on. The contract has no rule for the other URLs.

The options use three facts from the TanStack Router documentation, read on 2026-10-05. The pages describe the latest version. The app has version 1.170.38.

  • A pathless layout route wraps child routes "without requiring a matching path in the URL" (Routing concepts).
  • With no notFoundComponent, the router shows a default that "simply renders <p>Not Found</p>" (Not found errors).
  • A route sets its title in head, and a title of a nested route replaces the title of its parent (Document head management).
