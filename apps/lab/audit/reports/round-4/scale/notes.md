- Method: a real pull request run with one real row. Then N synthetic changed captures with the lengths of production: 2 rows in `visonaut_images` (the capture and its mask), 1 row in `visonaut_captures` with the metadata that `materializeBundle` builds (from the captures, tests, and comparison settings of the real Ariakit manifest: 1,317 bytes on average), and 1 row in `visonaut_comparison_rows` (row ID of 138 characters, the tuple of production). - **The run approval (D-WORK-04).** One transaction, 17 statements for any count, 5 rows for each change. It holds at 3,000 and at 30,000 changes on a local D1. At 300,000 changes it writes 1.5 million rows and 580 MB in one statement, which is above the documented limit. The settled words "in one transaction" then cannot hold.
- **The decision queue (D-RES-06).** One decision is one task row, and a run approval is also one task with no target list. The cost does not grow with the run. The route starts the saved decision with a lease of 30 seconds (`review.ts:650`): the run approval of 30,000 changes took 0.9 s locally.
- **The check updates and the three counts (D-OPS-07).** Each decision makes a status pass, and the pass counts the changes that need review with a scan of each comparison row of each active run (`run-status.ts:56-60`). With 10 active runs of 3,000 changes, one decision reads 30,000 rows. The check text itself has 3 numbers and no list, so it has no size problem.
- **The Queue and History lists.** The run list statement reads each comparison row of the 100 listed runs (finding D1-06). The no-regret list has the join order, which removes the rows of other runs. The rows of the listed runs stay: 100 runs of 3,000 changes are 300,000 rows for each read, and the answer of D-UX-05 reads the list each 15 to 60 seconds.
- **What a reviewer can do.** The settled answers give three scopes: one variant, one screenshot, and the run. With 3,000 changed screenshots a reviewer cannot open each one in a normal review. The search, the status filter, and the run approval are the tools. No settled answer gives a scope between one screenshot and the run. The maintainer selected that in D-WORK-04, with the options "groups with the same change" and "approve all seen" on the panel.
