  <li data-fact="measured">
    <strong>No secret.</strong> No token, no key, and no password of a real system is in the files.

  </li>
  <li data-fact="measured">
    <strong>The local path.</strong> <code>/Users/diegohaz</code> is in 441 files. 27 tracked files
    of the repository have it today, so the push adds nothing of a new kind.
  </li>
  <li data-fact="measured">
    <strong>The invented people of the lab.</strong>
    <code>apps/lab/src/fixtures/data/people.ts</code>, lines 52 to 57, has 6 invented reviewers. 3 of
    their GitHub user IDs and 4 of their logins belong to real accounts of other persons (read with
    the public GitHub API). 15 text files hold one of these logins or IDs: 2 code files, 3 design
    documents, 2 files of this record, and 8 files of one report. One probe result of that report
    holds the avatar address of one of these accounts. The fix is a task in each option: logins and
    IDs of no real account, before the push.
  </li>
  <li data-fact="measured">
    <strong>One count.</strong> The record says that the organization has 10 members. 6 are public
    members. The record names no member.
  </li>
  <li data-fact="counted">

    the Cloudflare Web Analytics token, which each page of the service sends to each visitor. Run
    data is private by the README, line 15, and these runs are of the public repository
    ariakit/ariakit.
  </li>
</ul>

<aside class="note">
  <p>
    <strong>What the repository does today.</strong>
    <span data-fact="counted"
      >It publishes this kind of record: <code>docs/evidence</code> has 248 tracked files, for
      example <code>deployed-session-probes.json</code> and
      <code>deployed-capability-boundaries.md</code>.</span
    >
    Your answer <a href="#decision-D-CODE-04">D-CODE-04</a> keeps such records in the repository,
    in <code>docs/history/</code>.
  </p>
  <p>
    <strong>What cannot be taken back.</strong> GitHub says that after a push the commits can stay
    "In any clones or forks of your repository" and "Directly via their SHA-1 hashes in cached views
    on GitHub" (<a
      href="https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository"
      >removing sensitive data</a
    >). A push that waits can be done on each later day.
  </p>
  <p>
    <strong>Limits.</strong> The scans used patterns, so they can miss a secret of an unknown form.
    The audit opened 6 of the 2,482 pictures. The file list is of 2026-10-07, 17:05 and again 17:30, while
    revision r8 was in work, so the counts can move by some files.
  </p>
</aside>
