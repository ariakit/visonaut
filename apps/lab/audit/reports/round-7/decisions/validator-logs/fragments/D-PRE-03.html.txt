<h4 id="code-names-in-log">Screenshot names in a failure message</h4>

<p>
  This is the open part of the row for <span data-findings="PKG-02"></span> in the list above. The
  CLI runs in the Submit job of the consumer repository, and what it prints is the log of that job.
  <span data-fact="measured">ariakit/ariakit is public (read on 2026-10-07).</span>
  <span data-fact="assumption"
    >So each person with a GitHub account can read that log (GitHub documentation; not tested with an
    account that has no access).</span
  >
  <span data-fact="counted"
    >Today no failure message of the CLI names a screenshot
    (<code>packages/cli/src/files.ts</code>, <code>png-comparison.ts</code>, and
    <code>local-comparison.ts</code>).</span
  >
</p>

<p>
  One example. The capture job accepts an image of 32 megapixels at most, and Submit accepts 2.1
  megapixels. <span data-findings="PKG-03"></span> A screenshot of 1248 by 1700 pixels passes the
  capture job and stops Submit. The name of a screenshot is its item key and its variant key, which
  the test code of the consumer writes (<code>packages/playwright/README.md</code>, lines 15 to 18).
</p>

<p class="wide">
  <strong>The relation to the public check.</strong> In
  <a href="#decision-D-OPS-07">D-OPS-07</a> you selected a public check with counts and with no
  screenshot name. The reason there is the earlier decision D25: the results of a review for each
  image stay private. A message of this decision is of another kind. It names a file that the CLI
  cannot read or accept (a size, a digest, a PNG that is not valid, settings that are missing). It
  never says that a screenshot changed, or that a reviewer approved or rejected it. So option 2 does
  not change your answer to D-OPS-07. If you want one rule for each public text, with no screenshot
  name in any of them, option 1 is that rule.
</p>

<p class="wide">
  <span data-fact="counted"
    >A key can hold only letters, digits, and the characters <code>. _ / -</code>, 256 at most
    (<code>packages/protocol/src/validate.ts</code>, lines 131 to 139).</span
  >
  So a key cannot hold a line break or a command for the log.
  <span data-fact="counted"
    >A display title of a test can hold each character but a control character
    (<code>validate.ts</code>, lines 81 to 92).</span
  >
  Option 2 prints the keys and never the title. A file in the step summary of GitHub has the same
  readers as the log, so it is not a separate option.
</p>

<aside class="note">
  <p>
    <strong>For a later customer.</strong> The CI log of a private repository is private in the same
    way as its code, so the keys show nothing to a person who cannot read the tests. A customer that
    makes keys from data outside its repository would show that data to the readers of its CI log.
  </p>
</aside>
