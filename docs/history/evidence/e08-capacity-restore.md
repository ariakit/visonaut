All resources in this drill are synthetic and isolated. No production database, Worker, bucket, or repository file was changed. The resources remain in place for inspection.

The updated Worker version was `6e17aa99-0bcb-4728-95f6-be026cd083a7` before synthetic secret rotation.
- Isolated source D1: `visonaut-e08-boundary-source-20260923` (`a226d597-ce01-4c4f-b759-abc1ecddae2a`). Isolated target D1: `visonaut-e08-boundary-target-20260923` (`a62679eb-9003-4c9f-94a0-83fdb93fa745`). The Queue Worker and R2 buckets all use the `visonaut-e08-boundary` or `visonaut-e08b` synthetic names. The original source-image corpus was read only.
- Capacity: source D1 physical size was **735,096,832 bytes** (91.28% of the provisional 768 MiB limit). The warm SQL export was **520,285,307 bytes** (96.91% of the provisional 512 MiB limit). The capacity padding comprised **15,500 synthetic audit rows**, 496,465,000 JSON text bytes, plus one synthetic expression index. These rows are SQL pressure only. They do not represent image objects. The source had two overlapping active synthetic uploading runs, both with zero images, alongside 3,582 real fixture image rows and an R2 corpus. The cold backup pinned both active runs; the restored target sanitized them to inactive state.
- Archive: 24 steps and 231 pages, from 04:54:26.932 to 04:58:26.158 UTC on 2026-09-23: **239.226 seconds**.
- Cold Queue backup: enqueued at 05:03:35.298 and complete at 05:28:03.826 UTC: **1,468.528 seconds**. It produced 9 groups, **7,414 verified R2 object entries**, 232,110,507 object bytes, and a 520,277,252-byte SQL snapshot. The manifest SHA-256 is `9482fb6a1f6470e9b4da967b91989eb808b2b4e3ad778ccaae7148a888f1df14`. The backup had no failure event. The Worker tail captured 63 Queue invocations with no non-OK outcome or exception; its maximum captured wall time was 177.698 seconds.
- Warm Queue backup: 05:28:33.189 to 05:30:16.402 UTC: **103.213 seconds**. It produced the same 9 groups and 7,414 object entries. Seven group IDs were reused, covering **all 7,414 objects and all 232,110,507 object bytes**. Two new groups were the zero-image active runs. The warm SQL snapshot was 520,285,307 bytes. Both backups ended `complete`, with zero unresolved backup events and zero lingering recovery pins.
- Restore: began at 05:31:21.345 UTC. The 520,285,307-byte SQL was downloaded and SHA-256 checked, then imported into the empty target D1 by 05:33:19.031 UTC. All 7,414 R2 objects and 232,110,507 bytes were replayed by 05:40:18.775 UTC. Database, archive, and object-reference checks plus sanitation completed at 05:42:06.580 UTC. Eleven selected D1 table fingerprints matched, every archived section matched, all referenced live objects were verified, and `PRAGMA foreign_key_check` returned no rows. Sessions, stored account tokens, and active runs were all zero after sanitation.
- Credential rotation reached recovery-ready state at 05:42:40.802 UTC. Old, still-unexpired access and ingest credentials returned HTTP 401; fresh credentials worked. The **complete measured RTO was 679.457 seconds (11 minutes 19.457 seconds)** from restore start. The target was not activated.
- An additional independent pass through the final-source `verifyGroupPage(...)` checked all 9 groups, 11 object pages, 7,414 objects, and 232,110,507 bytes in 65.456 seconds. It ran after the measured RTO. Source and target each had exactly 15,500 synthetic audit rows with the same 496,465,000 text bytes and first/last IDs.

One `/backup/state` read returned Cloudflare's `Currently processing a long-running export` error during cold D1 export. It recovered without backup failure. Cloudflare [documents](https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/export/) that a D1 database is unavailable for queries during a large export. The exact unavailable interval was not measured. This is a service availability consideration for scheduled backups.

This fixture covers two logical backup slots on one day. It does **not** demonstrate 30-day hosted retention or a workload with many active image-bearing runs. No cleanup or deletion was performed.
