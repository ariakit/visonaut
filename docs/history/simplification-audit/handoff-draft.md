## Invariants and evidence gates

No absent, failed, stale, or incomplete capture can mean an unchanged run or a passing App check. A candidate job gets no approval capability. Signed Submit must verify the real workflow, tested commit, source attempt, and complete shard set. A rerun shard needs new evidence; a visual job that GitHub did not rerun may keep its verified source-attempt artifact. If that one-day artifact expired, require a full visual rerun. The [capture evidence](./evidence/feedback-ops.md) and [Ariakit integration review](./evidence/feedback-integration.md) describe these boundaries.

Approval reuse still needs the full image, profile, policy, item, variant, and lineage identity. A copied approval is owned by the new run after that check. Active baselines and open reviews must pin every original byte they need. An expired closed run may show a summary, but it must not pretend that missing image bytes can be replayed. A required baseline image that is missing is a failure. These are the data gates for C01/C02/S05/S06, not optional cleanup.

Private app reads may reuse only a positive result for the same valid session, user, and repository. For example, an implementation may set `expiresAt = checkedAt + 60_000` after a successful GitHub check; it must reject that entry at expiry. Review writes still check current permission on every request. Public validated image URLs do not grant access to private run data.

The release job must publish the reviewed Changesets plan from the checked main commit. One selected `latest` or `next` tag applies to all eligible packages in that run. Changesets may skip a version that is already in npm, so the workflow must check the expected registry version and tag before it reports success. OIDC ties publication to the trusted workflow and source; it does not prove that the new archive matches an earlier test archive byte for byte. See the [release precedent](./evidence/feedback-r3-ariakit-release.md), [release-scope probe](./evidence/feedback-r3-release-scope.md), and [O10 record](./audit-data.json).

The artifact and small browser probes show that the proposed components and flows are possible. They do not prove deployed Cloudflare state, target-scale speed or cost, screen-reader output, or npm publication. Keep the existing fail-closed rules while each gate is tested. Record source, environment, workload, result, and limits for every implementation check.
