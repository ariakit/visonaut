# Visonaut hosted routing and sign-in observation

On September 22, 2026, the renamed service responded with valid TLS at `https://visonaut.com`, `https://preview.visonaut.com`, and `https://diagnostics.visonaut.com`. These are separate web Workers with separate D1 databases, R2 buckets, queues, and session secrets. The preview Worker remains separate because its queue consumer and comparator service binding need isolated resources.

The GitHub App is **Ariakit Visonaut** (App ID `5028451`, slug `ariakit-visonaut`). Its three exact OAuth callback URLs point to the three domains above. Its active webhook URL is `https://hooks.visonaut.com/webhooks/github`, with SSL verification enabled. The signed gateway verifies the original GitHub HMAC and configured repository IDs, then forwards events over service bindings. Recent `check_run` and `workflow_run` deliveries returned HTTP 202. Production and preview each held 147 `check_run`, 2 `check_suite`, 2 pull-request, 3 push, and 43 `workflow_run` receipts at the observation point. Those counts prove that the App reached the two Ariakit environments; they do not prove a complete launch cycle. The diagnostic receiver uses a separate configured repository.

An interactive GitHub OAuth sign-in completed on both the production and diagnostic domains. Each returned an authenticated Visonaut dashboard after the callback. A prior preview sign-in used its own callback. This shows that the callback registrations and deployed session paths work for one maintainer account. It does not establish session renewal, expiry, revocation, or cross-environment cookie refusal on the final source.

The gateway deployment came from the current working tree, before a reviewed release commit. Its [routing tests](../../apps/webhook/src/index.test.ts) cover signature failure, repository routing, affected-repository installation changes, App-wide revocation delivery, and downstream retry. A full test run passed 556 unit and integration tests and 52 Chrome browser checks. Verify the exact committed deployment again before readiness is marked complete.

No genuine merge-group delivery, OAuth revocation, or final Ariakit required-check cycle is established by these observations. The [nonproduction retirement guide](../operations/retire-preview-auth-at-cutover.md) is a contingency if an environment is deliberately closed; the gateway now carries revocation events to each active environment.
