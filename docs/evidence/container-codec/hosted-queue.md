# Integrated diagnostic Container path

On September 23, 2026, `visonaut-diagnostics-compare` routed actual synthetic GitHub captures through its D1-backed comparison queue, a private Cloudflare `basic` Container, and private R2 derived objects. The same service code uses `VISONAUT_CODEC_BACKEND=worker` in preview and production. Only diagnostics used `container` during this study. The pinned native codec uses Sharp 0.35.4 and libvips 8.18.6; its image digest is `sha256:1e66a2ca2e144fe4e5a2526e70c03624b5bf9fd2f73a99e34023ac99fd9840a3`. The Worker deployment version for the final image is `c75ee0f5-0ab2-4fde-87ef-b657724ffb3d`. SHA-256 of the tested local Container server, Worker connector, and Worker entry point was `b2ab9146b2a471214700d4dcec40fd5a0b96d0abb28634fd08986eba7956a5f1`, `143b0720003a593bd04cca3e2cc94fa237329c9ed9203e63b44c0454e030ea94`, and `11dd3942be68a5334013d96b79fbf7b5831a62be9ebb0beeaf7e11c87a6566a9`, respectively. The final image appended only the server patch layer to the earlier pinned image. It was verified to retain the Node command, non-root user, and working directory before upload.

The Container accepts only a bounded request from its Worker and has no Internet access. The Worker validates original R2 bytes and returned PNG dimensions, content digests, and comparison metadata before recording new R2 objects and D1 results. A changed pair produces a full-size red pixel mask; additions or removals have no mask. The queue keeps its normal lease, retry, and finalization path. On the final working tree, all 568 unit and integration tests, 52 Chrome review tests, five connector cases, three native server cases including `SIGTERM`, and seven deployment/release guard tests passed. The pinned Dockerfile build awaits the hosted PR check because this host has no Docker executable.

The changed-pixel fixture is [synthetic PR #20](https://github.com/ariakit/visonaut-diagnostics/pull/20). The review interface showed both red-card images and the generated mask. The final-run second mask was downloaded from private diagnostic R2, verified as 160 × 120 RGBA with 6,880 opaque red and 12,320 transparent pixels, and had SHA-256 `5b39d721653edcd90e7c99933818bf60323365559d66faf1e6b2264ceb936484`. The capture jobs passed. GitHub's actual **Visonaut** [App check](https://github.com/ariakit/visonaut-diagnostics/runs/107046018025) concluded failure on tested merge commit `e78b612fd0204f409f96bf8598043505b96fc8f3`; D1 status revision 241 recorded delivered failure. This is the expected gate for unapproved changed pixels. The diagnostic PR must not be merged as an approved baseline.

The first Container image ignored `SIGTERM` while Node ran as PID 1. The SDK's idle request did not stop its instance, and Cloudflare usage groups continued for more than 13 minutes after comparison work. An explicit Worker-side `stop()` also failed to make that image inactive. The repaired image handles `SIGTERM` by closing its HTTP server. With the Worker-side stop removed, the instance was observed inactive after the hosted green and red-card runs. This supports scale-to-zero behavior for the tested workload; it does not establish a cold-start percentile or an idle-time guarantee across regions.

Cloudflare Container Analytics queried at 04:36 UTC reported 31 metric minute groups and 32 usage minute groups for the diagnostic instance, across the failed and repaired image versions. The maximum sampled memory was 173,613,056 bytes; the final-image red-card minute sampled 167,440,384 bytes. These are **samples**, not continuous peaks or bounds for the full Ariakit image matrix. The two final-image usage groups, at 04:32 and 04:34 UTC, summed to 96,637,054,530 provisioned-memory byte-seconds, 360,001,081,712 disk byte-seconds, and 0.72 active CPU seconds. They include idle and startup time, and cannot establish a per-comparison charge or a steady duty cycle. Cloudflare [bills provisioned memory, disk, and active CPU while the instance runs](https://developers.cloudflare.com/containers/platform/pricing/), in addition to Worker and Durable Object use. At the documented `basic` size (1 GiB memory, 4 GB disk), an always-running 30-day month would be about $7.21 in memory and disk overage rates before included monthly usage, CPU, Workers, Durable Objects, Queue, R2, and D1. The repaired idle path avoids treating that always-on scenario as the measured monthly cost.

The final pinned image has both hosted paths and was observed inactive after each. Production and preview still need their Container app and Durable Object bootstrap. The study does not establish representative memory peaks, latency distributions, concurrency, sustained duty cycle, or a monthly incremental cost for the full Ariakit matrix. E01 remains partial until those checks and numeric limits pass.
