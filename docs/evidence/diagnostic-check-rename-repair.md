# Diagnostic legacy check lease proof and repair utility

On September 22, 2026, six diagnostic status deliveries became ambiguous after a rename. Cloudflare deployment `e2a278ad-95f0-4585-b99b-48e6017e21cb` served diagnostic Worker version `484bc367-4e66-4b05-bf21-3625256e883f` at 100% from 21:37:50 UTC until 22:43:56 UTC. The six alerts first appeared at 21:38:29–34 UTC. The [archived Worker version API](https://developers.cloudflare.com/api/typescript/resources/workers/subresources/beta/subresources/workers/subresources/versions/methods/get/) returned the exact 27-module release artifact. Its sender module SHA-256 is `29e8936a9cb251371f5bf1506f0903aa60fc196c227c8b3e69b008002da4e9b4`, byte-identical to the retained local deployment bundle. The recorded error appears once across the archived modules.

The archived sender fetched each check, rejected any name other than `Visonaut` with `wrong_check`, then would have tested the current lease and sent the PATCH. The six GitHub checks still had the exact former name `Ariviso`; their App ID, stored tested SHA, and `ariviso:<stored run ID>` external IDs matched. Therefore the recorded revision-47 attempts exited before PATCH. A remote `success` status by itself does not prove that outcome.

A read-only D1 and GitHub inspection at 2026-09-23 05:08 UTC found six revision-47 outbox rows in `sending`, each on attempt 1 of 5 with the exact `SecurityError: The check does not belong to this application and tested commit.` message. All six locks had `request_started=1`, `ambiguous=1`, and expired 21:50:28–33 UTC on September 22. Each had delivered revision 46. Five active runs wanted revision 243 (four `pending`, one `failure`); one inactive run wanted revision 241 with no current outbox row. A separate read-only query confirmed all six stored checks and runs belong to the diagnostic project and share the same external run identity. No lease token, run ID, or tested SHA is in this note.

The [one-time repair utility](../../apps/web/tooling/check-rename-repair/README.md) pins the six check IDs, original lease deadlines, expected revisions, run activity, and desired conclusions. It requires the fixed Worker version at 100% traffic, exact D1 row state and error, and exact GitHub check ID, App ID, tested SHA, external ID, and legacy name. It preflights all six and rechecks the deployment after the remote reads before a write. It then calls the existing `settleStatus` operation with the original token, revision 47, and `outcome: "not-sent"`. It omits `abandonedBefore`, which applies only when a request never started. The canonical D1 batch makes revision 47 obsolete and clears each lease without marking it delivered. The active scheduler can then deliver the five newer intents; the inactive event requires a separate exact guarded resolution.

The local fixture suite covers dry-run behavior, one successful settlement, repeat-run rejection, changed D1 state, a recorded uncertain PATCH error, wrong GitHub identity fields, a token changed during remote preflight, and a deployment change during preflight. Worker-level tests check Cloudflare's nested `result.deployments` response, reject split traffic and redirects, and use the Worker-supported manual redirect mode. The old flat-response parser and Node-supported `redirect: "error"` mode both failed the local Worker preflight before any D1 writes.

At 06:14 UTC on September 23, fixed diagnostic Worker version `8996328b-a965-4b82-b632-900832eeef2b` reached 100% traffic with bindings and cron schedule preserved. The local repair Worker then passed its read-only six-row preflight and settled all six exact revision-47 leases. D1 verification found each old outbox row `obsolete`, delivered revision 46 unchanged, and no remaining lease. By 06:19 UTC the five active current intents had delivered revision 243 and completed. Their real GitHub checks were named `Visonaut`, owned by App `5028451`, and concluded four successes and one expected failure; the historical `ariviso:` external IDs stayed bound to their original runs. The inactive run had no current intent. Its sole `check-delivery:106695088379:ambiguous` alert was resolved at 06:22 UTC with an atomic update guarded by the exact obsolete lease, inactive run, missing current outbox, project identity, and unresolved event. The local repair credentials were removed and the local Worker stopped.
